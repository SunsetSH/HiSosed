# Требования к продукту

## 1. Назначение

HiSosed — локальная интеграция Home Assistant для воспроизведения случайной последовательности коротких аудиофайлов в заданные временные окна через выбранные сущности `media_player`.

Проект берет за основу общую механику «БумСоседа»: случайные короткие события, собственные звуки и автоматическое окончание работы. Оригинальный проект закрыт, а его страница описывает случайную последовательность ударов, выбор своего звука, время остановки и наборы звуков для разных промежутков времени. HiSosed не переносит исходный код или аудиофайлы этого проекта.

## 2. Термины

- **Сценарий** — расписание, цели воспроизведения, сетка и набор аудио как единая настройка.
- **Временное окно** — локальный интервал, в котором сценарий может воспроизводить звук.
- **Клетка** — минимальный временной шаг сетки, по умолчанию 2 секунды.
- **Цикл** — последовательность из `N` клеток. После последней клетки создается новый паттерн.
- **Плотность** — доля активных клеток в цикле, 0–100%.
- **Активная клетка** — клетка, в начале которой выбирается случайный разрешенный аудиофайл и отправляется команда воспроизведения.
- **Поколение** — номер текущего запуска/конфигурации. Он нужен, чтобы устаревший callback не мог воспроизвести звук после остановки или изменения сценария.

## 3. Функциональные требования

### Установка и конфигурация

- **HS-FR-001**. Интеграция устанавливается вручную и через HACS как custom integration с уникальным доменом `hi_sosed`.
- **HS-FR-002**. Первичная настройка выполняется через UI Home Assistant (`config_flow`), без обязательного YAML.
- **HS-FR-003**. Пользователь может создать несколько независимых сценариев.
- **HS-FR-004**. Пользователь может переименовать, отключить и удалить сценарий.
- **HS-FR-005**. Все пользовательские строки доступны на русском и английском языках.

### Расписание

- **HS-FR-010**. Сценарий содержит время начала, время окончания и выбранные дни недели в часовом поясе Home Assistant.
- **HS-FR-011**. Поддерживается окно через полночь, например 22:00–01:00. Оно считается одним логическим запуском, начатым в выбранный день.
- **HS-FR-012**. Вне окна звук не запускается ни одним автоматическим callback этого сценария.
- **HS-FR-013**. При достижении конца окна ожидающие callback отменяются, даже если цикл еще не завершен.
- **HS-FR-014**. После перезапуска Home Assistant сценарий возобновляется только если текущее время все еще входит в окно; пропущенные клетки не воспроизводятся.
- **HS-FR-015**. Переходы летнего времени обрабатываются часовыми функциями Home Assistant: несуществующее местное время пропускается, повторяющееся не порождает второй параллельный запуск.

### Сетка и случайность

- **HS-FR-020**. Длительность клетки настраивается в безопасном диапазоне, предварительно 1–60 секунд; значение по умолчанию — 2 секунды.
- **HS-FR-021**. Количество клеток в цикле настраивается, предварительно 1–1800; UI также показывает продолжительность цикла.
- **HS-FR-022**. Плотность настраивается от 0 до 100%; UI может дополнительно показывать пресеты «редко», «иногда», «средне», «часто», «каждая клетка».
- **HS-FR-023**. Число активных клеток равно `floor(N × density / 100 + 0.5)` (округление половины вверх). Их позиции равномерно выбираются без повторов.
- **HS-FR-024**. После последней клетки создается новый паттерн с теми же параметрами. Когда существует более одного возможного паттерна, интеграция делает ограниченную попытку не повторять предыдущий паттерн полностью.
- **HS-FR-025**. Генератор допускает внедрение seed в тестах. В рабочем режиме seed формируется локально и не зависит от сети.
- **HS-FR-026**. Плотность 0% означает полную тишину в цикле; 100% — активность каждой клетки.
- **HS-FR-027**. Перегенерация во время работы атомарно заменяет только будущие клетки и не создает параллельный scheduler.
- **HS-FR-028**. Может поставляться небольшой опциональный стартовый набор только из собственных или совместимо лицензированных файлов. Для каждого файла сохраняются источник лицензии и SHA-256; файлы оригинального «БумСоседа» не переупаковываются без подтвержденного разрешения.

### Аудио и воспроизведение

- **HS-FR-030**. Сценарий содержит непустой список ссылок Media source на локальные аудиофайлы.
- **HS-FR-031**. Для каждого файла задаются отображаемое имя, признак включения и положительный вес выбора.
- **HS-FR-032**. В активной клетке один файл выбирается взвешенно-случайно из включенных файлов.
- **HS-FR-033**. Список можно менять без удаления сценария; изменения применяются со следующей еще не начавшейся клетки.
- **HS-FR-034**. Перед сохранением проверяются формат URI, допустимый тип медиа и существование хотя бы одного доступного файла.
- **HS-FR-035**. Пользователь может безопасно предпрослушать выбранный файл на выбранной цели вне расписания; это отдельное явное действие.
- **HS-FR-036**. Основной адаптер вызывает стандартное действие `media_player.play_media`; тип содержимого определяется по Media source/MIME, а не всегда жестко задается как MP3.
- **HS-FR-037**. В MVP политика пересечения — `replace`: новое активное событие может заменить еще играющий клип. Документация рекомендует клипы не длиннее клетки. Политики `skip_if_playing` и `queue` рассматриваются после аппаратных испытаний.
- **HS-FR-038**. Ошибка одного плеера или файла фиксируется как обезличенное состояние ошибки и не создает быстрый бесконечный retry. Следующая клетка остается независимой.
- **HS-FR-039**. При нескольких целях сбой одной цели не блокирует остальные.

### Управление и наблюдаемость

- **HS-FR-040**. Доступны действия `start`, `stop`, `regenerate` и `preview` с проверяемой схемой параметров.
- **HS-FR-041**. `stop` идемпотентен и немедленно инвалидирует поколение scheduler до любых ожидаемых операций.
- **HS-FR-042**. Для каждого сценария есть switch включения расписания и сенсоры состояния/следующего события; диагностические сущности отключены по умолчанию.
- **HS-FR-043**. Состояния как минимум: `disabled`, `waiting`, `running`, `stopping`, `error`.
- **HS-FR-044**. UI показывает текущий цикл и клетки как прошлые, текущую, будущие активные и будущие тихие. Сетка — представление состояния backend, а не самостоятельный scheduler в браузере.
- **HS-FR-045**. Ручной `start` по умолчанию все равно ограничен ближайшим концом временного окна. Обход окна допускается только как отдельная явно названная будущая возможность и не входит в MVP.

### Сохранность и конкурентность

- **HS-FR-050**. Настройки сценариев имеют UUID, версию схемы и целочисленную ревизию.
- **HS-FR-051**. Сохранение выполняется целиком либо оставляет предыдущую корректную версию; поврежденные данные не активируются.
- **HS-FR-052**. Для одного сценария существует не более одного scheduler task; изменение, остановка и выгрузка config entry сериализованы `asyncio.Lock`.
- **HS-FR-053**. Любой callback проверяет `generation_id`, актуальную ревизию, активное окно и состояние сценария непосредственно перед вызовом плеера.
- **HS-FR-054**. После аварийного завершения восстанавливаются конфигурация, номер цикла, сохраненный паттерн и логическая позиция по текущему времени. Пропущенные события не догоняются.
- **HS-FR-055**. Удаление или выгрузка интеграции отменяет все подписки и callback.

## 4. Нефункциональные требования

- **HS-NFR-001, local-first**. Расписание, генерация, хранение и выбор файлов работают без аккаунта и внешнего сервера. Сетевой доступ допустим только внутри локальной сети до выбранного медиаплеера и самого Home Assistant.
- **HS-NFR-002, async**. В event loop нет блокирующего файлового I/O, декодирования аудио или `sleep`-циклов.
- **HS-NFR-003, точность**. Scheduler планирует абсолютную следующую границу клетки, а не прибавляет задержку к фактическому времени выполнения; накопительный дрейф не превышает одного периода event loop.
- **HS-NFR-004, приватность**. В логах и diagnostics нет пользовательских путей, имен файлов/сценариев и содержимого медиа. Разрешены UUID, счетчики и типизированные коды ошибок.
- **HS-NFR-005, совместимость**. Backend следует поддерживаемой версии Python конкретного релиза Home Assistant. UI адаптивен для Android companion app и браузера Windows.
- **HS-NFR-006, доступность**. Все элементы доступны с клавиатуры, имеют текстовые подписи и не кодируют состояние только цветом.
- **HS-NFR-007, нагрузка**. Отображение сетки не создает отдельную запись Recorder на каждую клетку; частые данные передаются подпиской WebSocket или агрегированным состоянием.
- **HS-NFR-008, безопасность файлов**. При будущем upload проверяются имя, расширение/MIME, размер, конечный путь и квота; MVP использует встроенную загрузку Home Assistant в `/media`.

## 5. Проверяемая семантика алгоритма

Для `N = 10` и плотности `30%` каждый цикл содержит ровно три активные клетки. Например:

```text
цикл 17: · ■ · · ■ · · · ■ ·
цикл 18: ■ · · · · ■ · ■ · ·
```

На границе активной клетки backend выбирает ровно один разрешенный файл. На границе тихой клетки команда не отправляется. После клетки 10 создается цикл 18. Если временное окно закончилось между клетками, цикл прерывается.

Такое «точное количество + случайные позиции» лучше соответствует требованию «частота та же, паттерн иной», чем независимый бросок вероятности в каждой клетке, при котором фактическая плотность короткого цикла могла бы сильно плавать.

## 6. Критерии готовности MVP

MVP принимается, когда:

1. сценарий создается и полностью редактируется из UI;
2. на фиксированном seed модульный тест получает ожидаемую сетку и выбор аудио;
3. в 100 последовательных циклах каждого размера соблюдается точное число активных клеток;
4. `stop`, удаление и конец окна не допускают позднего `play_media`;
5. перезапуск внутри окна планирует только следующую будущую клетку;
6. перезапуск вне окна не воспроизводит звук;
7. проверены минимум два разных типа плеера или один целевой плеер плюс mock с задержками/ошибками;
8. пройдены targeted tests, полный pytest, Ruff, Hassfest и HACS validation;
9. установка и удаление проверены на поддерживаемом Home Assistant, а UI — на Android и Windows;
10. документация явно объясняет, что 100% активных клеток не равно гарантированному gapless-воспроизведению.
