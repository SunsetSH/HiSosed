# ADR-0003: дорожки, библиотека звуков, пресеты, профили колонок и хранилище v2

- Статус: принято для v0.2.0
- Дата: 2026-11-16
- Связанные требования: HS-FR-003, 010–015, 022, 024, 030–039, 042–045, 050–055, HS-NFR-004, 007, 008
- Частично заменяет: ADR-0002 (раздел «Рекомендуемая конфигурация»), ARCHITECTURE §12 (пункт про собственный upload)

## Контекст

Версия 0.1 позволяла одно окно в день, одну сетку и один список URI на сценарий. Пользователь (HA в Proxmox, колонка по Bluetooth или jack 3.5, удалённый доступ из браузера) попросил:

- несколько одновременно играющих дорожек, у каждой своё время действия с перерывами по дням недели;
- импорт файла с компьютера в один клик;
- категории звуков, пресеты для быстрой смены звучания, чекбоксы дорожек и звуков без удаления;
- адаптацию к Bluetooth/jack-колонке при HA в виртуальной машине.

## Решения

1. **Модель.** `Scenario` (в UI «программа») хранит общие колонки и недельное расписание и содержит 1–20 `Layer`. У дорожки есть `enabled`, ссылки на звуки библиотеки (`SoundRef`: `enabled`, `weight`), своя сетка, необязательные своё расписание, свои колонки, громкость и политика пересечения `replace|skip`. Расписание задаётся списком интервалов на каждый день (до 8). `end <= start` переходит через полночь, `start == end` означает сутки. Соприкасающиеся интервалы склеиваются в одно окно, чтобы у дорожки никогда не было двух планировщиков.
2. **Библиотека звуков** глобальная (`Sound`: имя, категория, URI, размер, `managed`). Файлы лежат в `<media>/hi_sosed/`. Подпапка при сканировании становится категорией (удобно для Samba). Удаление звука, который где-то используется, требует `force` и вычищает ссылки из дорожек и пресетов.
3. **Собственный upload остаётся** (вопреки ARCHITECTURE §12): встроенный media upload Home Assistant не создаёт запись в библиотеке и не проверяет содержимое. Защита по HS-NFR-008: только админ, allowlist расширений, проверка сигнатуры контейнера, лимит 25 МБ на файл и 1 ГБ на библиотеку, потоковая запись в `.part` и `os.replace`, имя файла генерирует сервер (UUID). Исходное имя хранится только как отображаемое.
4. **Пресет** — снимок микса (`enabled`, звуки, плотность, громкость) каждой дорожки. Расписания и колонки он не меняет, поэтому переключение не ломает окна. Применение атомарно под lock и увеличивает ревизию.
5. **Ручной запуск** (`run_now`, HS-FR-045) — явно названная функция: временное окно `[now, now+N]` поверх расписания. Оно хранится в runtime checkpoint и переживает рестарт. `stop` теперь сохраняет `enabled=false`, иначе после рестарта «остановленный» сценарий снова заиграл бы.
6. **Тишина** (`snooze`) — глобальный запрет воспроизведения до момента T. Пропущенные клетки не догоняются.
7. **Профили колонок** (`OutputProfile`): тип, громкость, прогрев (turn_on и тишина до окна), keep-alive (тихий WAV в паузах длиннее N секунд, только внутри идущего окна), компенсация задержки (команда уходит раньше, но не раньше начала окна). Звук по-прежнему идёт только через `media_player.*` (ADR-0001). Прямого доступа к ALSA/Bluetooth нет (ADR-0002 в силе).
8. **Одновременность.** Один `media_player` играет один поток, это свойство плееров, а не HiSosed. Для настоящего наложения дорожки назначаются разным плеерам. Скрипт `scripts/proxmox/audio-node.sh` поднимает N экземпляров MPD на одном выходе PipeWire, который их смешивает. На общем плеере политика `skip` не даёт второстепенной дорожке перебить звук, начатый другой дорожкой меньше одной клетки назад. Микширование на стороне HiSosed (ffmpeg/renderer) отложено: оно требует кодеков, временных файлов и квот (ARCHITECTURE §9).
9. **Воспроизведение.** Каждой цели отдельный вызов `blocking=True` с таймаутом 10 с через `asyncio.gather`. Ошибка или таймаут одной цели не мешает остальным (HS-FR-038/039). Цель с незавершённым вызовом пропускается (`target_busy`), это исключает лавину задач. Цель `unavailable` не вызывается. `media_content_type` остаётся `music`: интеграции, понимающие media-source, сами берут MIME из resolve. MIME хранится в библиотеке для диагностики (отклонение от буквы HS-FR-036).
10. **Хранилище v2** (`hi_sosed.scenarios`, version 2): `{sounds, outputs, scenarios}`. Миграция v1→v2 — чистая функция `models.migrate_v1`. Отдельный Store `hi_sosed.runtime` (отложенная запись 5 с) хранит паттерн и номер цикла каждой дорожки, ручные запуски и тишину (HS-FR-054).
11. **Lock и запись Store.** Запись `ScenarioStore` выполняется под `ScenarioManager._lock`. Это ограниченная по времени executor-операция, и она нужна, чтобы память менялась только после успешной записи (HS-FR-051). `play_media`, upload и удаление файлов под lock не ждём.
12. **Наблюдаемость.** Шина событий больше не используется: dispatcher и WS-подписка `hi_sosed/subscribe` не попадают в Recorder. Сущности на программу: `switch` расписания, `switch` каждой дорожки, `select` пресета, `sensor` состояния (`disabled|idle|waiting|running|snoozed|error`). Состояние сенсора пишется только при реальном изменении (HS-NFR-007).
13. **Домен без HA.** `models.py`, `engine.py`, `audio.py` не импортируют Home Assistant. Ошибки домена — `HiSosedError(code)`, адаптеры переводят их в `ServiceValidationError`/WS `send_error`. Часовой пояс передаётся параметром. Несуществующее при DST время сдвигается за разрыв, повторяющееся даёт одно окно.

## Последствия

- Изменение звуков, весов и громкости не перезапускает цикл (`timing_signature`). Изменение сетки, расписания, колонок или переключателей перезапускает только затронутые дорожки.
- Ручной запуск и пресеты меняют поведение, которое в v0.1 считалось вне MVP. Это явные, подписанные в UI действия, а не скрытый обход окна.
- Проверено только в тестах и jsdom. Реальные Bluetooth/MPD/VLC, задержки A2DP и скрипт аудиоузла на железе не проверены.
