# ADR-0004: подключение аудиоузла из панели

- Статус: принято для v0.2.0
- Дата: 2026-11-16
- Связанные требования: HS-FR-005, HS-NFR-008; ADR-0001, ADR-0002, ADR-0003 п. 8
- Уточняет: ADR-0002 (рекомендуемая схема для HA в Proxmox)

## Контекст

Пользователь держит Home Assistant OS в ВМ Proxmox, а колонку подключает прямо к серверу: усилитель через гнездо 3.5 мм или Bluetooth-колонку. Ручная схема (создать LXC, дописать конфиг, поставить пакеты, добавить MPD на каждый порт) оказалась слишком сложной. По ходу всплыли ловушки:

- Audio Device в настройках ВМ — виртуальная карта: SPICE передаёт звук в окно просмотра, Dummy его выбрасывает. К гнезду сервера она не ведёт.
- Дополнение VLC играет через звук ВМ HA, а встроенную карту хоста эта ВМ не видит. Если добавить его интеграцию вручную, она просит пароль.
- В непривилегированном LXC `/dev/snd` принадлежит `nobody`, и открыть его нельзя.
- В шаблоне Debian нет `sudo`.
- Bluetooth-сокеты ядра работают только в начальном сетевом пространстве имён (`init_net`), поэтому в LXC с собственной сетью Bluetooth не поднять.

Пользователь просит управлять всем из одного места.

## Варианты

1. **Proxmox API из HA.** Отклонён:
   - API-токен не может ни выставить `lxc.*`-ключи (это разрешено только `root@pam`), ни выполнить команду внутри контейнера;
   - пароль root гипервизора хранить в HA недопустимо.
2. **Установка на сам хост Proxmox.** Отклонён: на гипервизор пришлось бы ставить PipeWire, MPD и BlueZ.
3. **Собственный MPD-клиент или HTTP-агент узла в HiSosed.** Отклонён: это новый сетевой протокол, зависимость и фоновый сервис. Встроенная интеграция MPD уже даёт `media_player`.
4. **Одна команда на хосте + кнопка «Подключить» в панели.** Принят.

## Решение

1. **`scripts/proxmox/host-setup.sh`** запускается одной командой в Shell хоста. Панель показывает её готовой к копированию.
   - **`--mode jack`:** привилегированный LXC Debian 12 `hisosed-audio`, `lxc.cgroup2.devices.allow: c 116:* rwm` и bind-mount `/dev/snd`. Внутри ставится `audio-node.sh` через `pct push` и `pct exec`. Привилегированность — осознанный компромисс: в контейнере работают только MPD и PipeWire, но root контейнера близок к root хоста. Звуковые карты хоста целиком отдаются контейнеру.
   - **`--mode bluetooth`:** ВМ Debian 12 `hisosed-bt` из официального cloud-образа (generic: в ядре cloud-образа нет драйверов Bluetooth). USB Bluetooth-адаптер хоста пробрасывается по `VID:PID`; адаптер находится по классу интерфейса `e0/01/01` в sysfs. Установка идёт через cloud-init vendor-data: файл-сниппет с встроенным `audio-node.sh` и `qemu-guest-agent`. Если ни у одного хранилища нет типа `snippets`, создаётся отдельное dir-хранилище `hisosed-snippets`, существующие хранилища не меняются. Сопряжение проходит интерактивно в том же Shell через `qm guest exec` (`hisosed-bt-scan`, `hisosed-bt-pair MAC`).
   - **Общее для обоих режимов:**
     - повторный запуск находит существующий узел по имени и только переустанавливает его;
     - `--pair` заново выполняет сопряжение;
     - `--check` запускает `hisosed-check`: показывает карты, выходы и плееры и проигрывает тестовую фразу;
     - в конце скрипт печатает адрес узла.
2. **`audio-node.sh`** дополнен:
   - в LXC нет udev, и WirePlumber не видит карты, хотя `/dev/snd` проброшен. Если аналоговый sink не появился сам, первый не-HDMI PCM из `/proc/asound` объявляется статическим узлом PipeWire (`context.objects`, `api.alsa.pcm.sink`, `hisosed_jack`). Найденный автоматически sink не трогается: на обычной машине с udev два открытия одного `hw:` конфликтовали бы;
   - режим jack при каждой загрузке снимает mute с кодека (`hisosed-unmute.service`: на хосте Proxmox нет alsa-utils, и после перезагрузки кодек приглушён) и выбирает аналоговый выход вместо HDMI;
   - режим Bluetooth ставит non-free-firmware для адаптеров Intel и Realtek;
   - появились `hisosed-check` и неинтерактивный `hisosed-bt-pair MAC`;
   - `sudo` больше не нужен.
3. **WS `hi_sosed/node/connect`** (`require_admin`), адаптер `nodes.py`:
   - адрес проходит строгую проверку: IP или DNS-имя, без схемы, порта и пробелов, иначе код `invalid_host`;
   - для портов `6600..6600+N-1` HiSosed запускает **встроенный config flow MPD** (`flow.async_init(source=user, data={host, port})`). HiSosed сам по сети не ходит, соединение открывает интеграция MPD. Новых зависимостей в `manifest.json` нет;
   - уже добавленный `host:port` не дублируется (`exists`);
   - если flow вернул форму с ошибкой, flow прерывается (`cannot_connect`), чтобы не висеть незавершённым;
   - если интеграция не загрузилась, статус `unavailable`;
   - новым устройствам задаётся `name_by_user` («HiSosed 1», «HiSosed Bluetooth 2»), потому что все MPD-устройства иначе называются «Music Player Daemon»;
   - колонкам без профиля создаётся `OutputProfile` выбранного типа. Для Bluetooth сразу ставятся рекомендованные прогрев, keep-alive и компенсация задержки. Существующие профили и имена не трогаются;
   - ответ: `{players: [{port, status, entity_id}], local_url}`. При `local_url=false` панель предупреждает, что у HA нет LAN-адреса и MPD не сможет скачать звук.
4. **Панель.** Во вкладке «Колонки» появилась карточка «Подключить колонку к серверу»: тип подключения, число плееров, команда для Proxmox, поле адреса и кнопка «Подключить». Неверный путь через USB-карту в ВМ HA и VLC убран из панели. Диагностика и ручное добавление MPD перенесены в блок «Если что-то не получается».

## Последствия

- Пользователь делает три действия: копирует команду, вставляет её в Proxmox, вписывает адрес. Остальное автоматизировано.
- HiSosed по-прежнему играет только через `media_player.play_media` (ADR-0001) и не трогает ALSA и BlueZ из HA (ADR-0002). Звуковое железо обслуживает отдельный узел.
- Скрипты пока проверены только синтаксически (`sh -n`) и по документации Proxmox. Нужна проверка на реальном хосте: PVE 8 и 9, встроенный HDA-кодек, USB-карта, адаптеры Intel, Realtek и CSR.
- `host-setup.sh` скачивает cloud-образ Debian и шаблон LXC из официальных источников (`cloud.debian.org`, `pveam`) и `audio-node.sh` с GitHub. В HA сетевых вызовов не добавилось.
